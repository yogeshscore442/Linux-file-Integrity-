# FIM Audit Logs Directory

This directory stores runtime audit trails and event streams generated by the Linux File Integrity Monitor.

## Log Files Generated

1. **`fim_audit.log`**:
   - Human-readable standard text log file.
   - Contains timestamped operational events (`INFO`, `WARNING`, `CRITICAL`, `ERROR`).
   - Format: `[YYYY-MM-DD HH:MM:SS,sss] [LEVEL] [LOGGER] Message`

2. **`fim_events.jsonl`**:
   - High-fidelity structured JSON Lines log.
   - Every line represents a discrete security or operational event.
   - Designed for seamless ingestion into SIEM platforms (Splunk, Wazuh, ELK/Elasticsearch, Microsoft Sentinel).
   - Fields include: `event_id`, `timestamp`, `event_type`, `severity`, `file_path`, `details`, `host`.

## Production Security Best Practice
In a production Linux hardening setup:
- Forward logs immediately to an out-of-band remote syslog server (`rsyslog` or `syslog-ng`) to prevent an attacker with local root access from wiping the integrity logs.
- Set append-only file attributes using `chattr +a logs/fim_audit.log` on Linux.
